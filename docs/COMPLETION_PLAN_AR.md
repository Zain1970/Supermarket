# خطة إكمال مشروع السوبرماركت

> الحالة: خطة تنفيذ ومراجعة. وجود هذه الوثيقة لا يعني أن البنود قد نُفذت أو اجتازت الاختبارات.

## قاعدة العمل

- التطوير على فرع مستقل وفتح Pull Request للمراجعة؛ لا دمج ولا نشر تلقائي.
- عدم تشغيل ترحيلات على قاعدة إنتاج أو إدخال بيانات حقيقية خلال التطوير.
- عدم الادعاء بنجاح اختبار إلا بوجود تشغيل CI أو نتيجة محلية موثقة.
- حماية عزل بيانات المتاجر، وصلاحيات الأدوار، وسلامة المخزون والعمليات المالية.

## المرحلة 1 — خط أساس قابل لإعادة الإنتاج

- [ ] تثبيت إصدار Node.js المدعوم في CI وملفات المشروع.
- [ ] إنشاء lockfile متوافق ومراجعته؛ استخدام `npm ci` في CI.
- [ ] مراجعة نتائج `npm audit` ومعالجة الثغرات العالية والحرجة دون ترقيات كاسرة عمياء.
- [ ] تثبيت أو توثيق إصدارات PostgreSQL المستخدمة في الاختبارات.
- [ ] تشغيل Prisma validate/generate وtypecheck والاختبارات والبناء من تثبيت نظيف.

## المرحلة 2 — مراجعة أمنية متعددة المتاجر

- [ ] التحقق من أن كل مسار يقيّد الاستعلامات بمعرّف المتجر والعضوية والصلاحية المطلوبة.
- [ ] اختبارات رفض الوصول إلى متجر آخر، بما في ذلك قراءة/تعديل المنتجات والعملاء والمبيعات والمشتريات والمخزون.
- [ ] مراجعة إدارة الجلسات، ملفات تعريف الارتباط، حدود محاولات تسجيل الدخول، والتحقق من المدخلات.
- [ ] مراجعة أسرار البيئة وعدم تضمين كلمات المرور أو مفاتيح الإنتاج في المستودع والسجلات.
- [ ] فحص الاعتماديات ورفع ملخص بالثغرات المتبقية مع مبررات واضحة.

## المرحلة 3 — صحة العمليات التجارية

- [ ] تغطية إنشاء البيع والدفعات والمرتجعات والمشتريات وتسويات المخزون بمعاملات ذرية.
- [ ] اختبارات مفاتيح Idempotency للتكرار والتزامن، مع التأكد من عدم مضاعفة الكميات أو الدفعات.
- [ ] توثيق حدود مرتجعات المبيعات الحالية: لا تُعامل كاسترداد نقدي أو تسوية ذمم ما لم تُنفذ وتُختبر صراحة.
- [ ] تنفيذ دورة المشتريات على مراحل: مسودة، اعتماد، استلام، إلغاء، ومرتجعات موردين مع قواعد مخزون واضحة.
- [ ] تصميم مدفوعات الموردين والضرائب وائتمان العملاء قبل التنفيذ، مع اختبارات دفتر حسابات ومطابقة.
- [ ] إضافة قيود وفهارس قاعدة البيانات التي تضمن عدم خلط بيانات المتاجر.

## المرحلة 4 — اختبارات قاعدة البيانات والتكامل

- [ ] تشغيل اختبارات على PostgreSQL حقيقي مؤقت، لا الاكتفاء بالمحاكاة.
- [ ] اختبار قاعدة جديدة وترقية قاعدة موجودة من حالة ترحيل موثقة.
- [ ] اختبار تعارضات Serializable وإعادة المحاولة والاستجابات المتوقعة.
- [ ] مراجعة سجل Prisma migrations ومقارنته بالمخطط قبل أي ترحيل.
- [ ] تجربة الاستعادة من نسخة احتياطية على بيئة منفصلة.

## المرحلة 5 — الواجهة العربية وتجربة المستخدم

- [ ] ربط كل شاشة بواجهات API الفعلية وإزالة أي بيانات تجريبية متبقية.
- [ ] إكمال شاشات الموردين والمشتريات وإعدادات المتجر ولوحة الإدارة حسب الصلاحيات.
- [ ] توفير حالات التحميل والفراغ والخطأ والنجاح، والتحقق من المدخلات ورسائل عربية مفهومة.
- [ ] التحقق من RTL والتجاوب على الهاتف وإمكانية الوصول.
- [ ] معالجة حدود الترقيم؛ لا تُظهر القائمة الجزئية على أنها جميع السجلات.
- [ ] اختبارات E2E لمسار تسجيل الدخول والبيع والدفعات والمخزون والمشتريات وإدارة الاشتراكات.

## المرحلة 6 — التشغيل والنشر

- [ ] توثيق إعدادات التطوير والاختبار والإنتاج ومتغيرات البيئة المطلوبة.
- [ ] إضافة فحوص صحة وجاهزية وسجلات لا تكشف بيانات حساسة.
- [ ] توثيق TLS وإعدادات الوكيل والرؤوس الأمنية وحدود الطلبات.
- [ ] تحديد سياسة النسخ الاحتياطي والاحتفاظ والاستعادة واختبارها.
- [ ] إعداد خطوات نشر وترحيل وتراجع واضحة، مع بوابة موافقة بشرية.
- [ ] مراجعة صلاحيات مسؤول المنصة وتهيئة الحساب الأول بشكل آمن.

## معايير قبول الإصدار

لا يُعلن المشروع جاهزًا للإنتاج إلا بعد تحقق جميع الشروط التالية:

1. نجاح CI على أحدث commit، بما يشمل التثبيت النظيف والاختبارات والفحص والبناء.
2. اجتياز اختبارات PostgreSQL والتكامل وE2E ذات المسارات التجارية الأساسية.
3. إغلاق عوائق الأمن العالية/الحرجة أو توثيق قبول المخاطر من المسؤول.
4. مراجعة بشرية للتغييرات والترحيلات والصلاحيات.
5. نجاح تجربة الاستعادة والنشر على بيئة تجريبية مماثلة للإنتاج.
6. عدم وجود أسرار أو بيانات مستخدمين حقيقية في المستودع أو سجلات CI.
