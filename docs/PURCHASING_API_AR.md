# واجهات الموردين والمشتريات

هذه الواجهات مضافة على فرع التطوير `codex/suppliers-purchasing-foundation`. تحتاج كل الطلبات إلى جلسة صالحة وعضوية مناسبة في المتجر. كل قراءة وكتابة مقيدة بمعرّف المتجر الموجود في المسار.

## الموردون

### عرض الموردين

`GET /stores/:storeId/suppliers?q=search&page=1&pageSize=25&includeInactive=false`

- متاح لمالك المتجر والمدير وموظف المشتريات.
- البحث يشمل الاسم والهاتف والبريد الإلكتروني والرقم الضريبي.
- `pageSize` من 1 إلى 100. الموردون غير النشطين مخفيون افتراضيًا.
- الاستجابة: `{ suppliers, pagination: { page, pageSize, total } }`.

### إنشاء مورد

`POST /stores/:storeId/suppliers`

الحقول:
- مطلوب: `name` (1–180 محرفًا).
- اختياري: `phone`, `email`, `address`, `taxNumber`, `notes`.

يُسجل الإنشاء في سجل التدقيق. البريد الإلكتروني يُحفظ بحروف صغيرة.

### تعديل مورد أو تعطيله

`PATCH /stores/:storeId/suppliers/:supplierId`

يمكن إرسال أي حقل من حقول المورد، أو `isActive: false` لتعطيله دون حذف السجل. لا يمكن إرسال جسم فارغ.

## المشتريات

### عرض فواتير المشتريات

`GET /stores/:storeId/purchases?q=search&supplierId=id&page=1&pageSize=25`

يعرض الفواتير مع المورد وبنود الفاتورة، ويتيح البحث برقم الفاتورة أو اسم المورد.

### تسجيل فاتورة مشتريات مستلمة

`POST /stores/:storeId/purchases`

يجب إرسال ترويسة `Idempotency-Key` بطول 8–100 محرف لتقليل خطر تكرار الاستلام.

مثال جسم الطلب:

```json
{
  "supplierId": "supplier-id",
  "purchaseNumber": "PUR-2026-0001",
  "notes": "فاتورة توريد",
  "items": [
    { "productId": "product-id-1", "quantity": "12", "unitCost": "250.00" },
    { "productId": "product-id-2", "quantity": "3.500", "unitCost": "180.50" }
  ]
}
```

السلوك الحالي:
1. يتحقق الخادم من أن المورد نشط والمنتجات نشطة وتتبع المتجر نفسه.
2. يمنع تكرار المنتج داخل الفاتورة، ويتحقق من أن الكميات موجبة والتكلفة غير سالبة.
3. يحسب إجمالي كل بند والإجمالي النهائي على الخادم؛ لا يثق في إجمالي مرسل من العميل.
4. يسجل الفاتورة بحالة `RECEIVED`، ويزيد مخزون كل منتج ويحدث آخر تكلفة شراء له.
5. يسجل حركة مخزون من النوع `PURCHASE` وسجل تدقيق داخل معاملة `Serializable` واحدة. أي فشل في أحد الخطوات يلغي المعاملة كلها.
6. يحفظ بصمة الطلب ومفتاح منع التكرار. إعادة الطلب بالمفتاح نفسه والمحتوى نفسه تعيد الفاتورة السابقة، أما استخدام المفتاح نفسه بمحتوى مختلف فيُرفض.

## الصلاحيات وحدود الإصدار الحالي

- القراءة والكتابة متاحتان لمالك المتجر ومديره وموظف المشتريات.
- لا يمكن استخدام مورد أو منتج من متجر آخر.
- حذف المورد غير متاح؛ استخدم التعطيل لتبقى السجلات التاريخية سليمة.
- الفاتورة تُستلم مباشرة عند إنشائها في الإصدار الحالي. مسودات الشراء والاعتماد والإلغاء ومرتجعات الموردين وضريبة المشتريات والمدفوعات للموردين لم تُنفذ بعد.
- يجب تشغيل ترحيلات Prisma قبل استخدام هذه المسارات. لم تُعلن جاهزية الإنتاج قبل تشغيل CI واختبارات PostgreSQL والتكامل في بيئة حقيقية.
